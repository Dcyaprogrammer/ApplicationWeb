## Auth / Save Data Implementation Follow-up

Initial inspection showed that registration and login were partially implemented:

- Supabase Auth was already connected.
- Email/password sign in and sign up existed in `AuthModal`.
- Anonymous guest login existed and was used by the home screen.
- However, `Login / Save Data` was misleading because game runs were still saved only to `localStorage`.
- `SupabaseRuntimePersistence` existed but was not wired into `gameStore`.
- `runs.user_id` was present in the schema, but runtime serialization never wrote it.
- `runs.id` and `run_card_history.id` have no database default, so frontend inserts needed to generate ids explicitly.
- `authStore.initialize()` registered a new auth listener every time it was called.

Changes made:

- Added explicit frontend id generation for Supabase run and history records.
- Added `user_id` support to runtime run serialization.
- Updated `SupabaseRuntimePersistence` to create, load, update, and filter runs by the active user id.
- Updated `gameStore` so logged-in non-anonymous users save through Supabase, while guest users keep using localStorage.
- Added fallback to localStorage if cloud run creation fails.
- Updated `AuthModal` to use `authStore` actions instead of calling Supabase directly.
- Added email-confirmation messaging for sign-up flows where Supabase does not immediately create a session.
- Fixed duplicate Supabase auth listener registration in `authStore`.
- Added `npm run db:check:supabase:persistence` to verify cloud run persistence end-to-end.

Validation:

- `npm run build` passed.
- Targeted ESLint for changed auth/runtime files passed.
- `npx prisma validate --schema prisma/schema.prisma` passed.
- `npm run db:seed:dry` passed.
- `npm run db:check:supabase` passed with 80 cards and 1 balance config.
- `npm run db:check:supabase:catalog` passed with `timeline_start` and 80 runtime cards.
- `npm run db:check:supabase:persistence` passed: it created a temporary run, appended one history row, saved runtime state, read it back, and cleaned the test data.
- Local dev app responded with HTTP 200 at `http://localhost:5173/`.

Current state:

- Guest play still works.
- Logged-in users now get cloud-backed run persistence.
- Existing guest progress is not automatically migrated into a logged-in account yet.
- Password reset and profile screens are still not implemented.
- Full repo lint still fails because of older unrelated files in `docs/.astro`, `neo-brutalism-ui-library`, `AuthScreen`, and a few pre-existing components.
